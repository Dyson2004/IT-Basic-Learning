0013 — 路由與 VPC：雲端的私人領地

對應模組: Module 6 — 路由與 VPC
預計時間: 30 分鐘

想像 VPC 就像是你買了一塊「私人莊園」。在莊園裡面，你可以自由規劃：

1. 前院 (Public Subnet)：設有大門（Internet Gateway），允許訪客進入，適合放你的「接待處」 (例如：網站伺服器)。
2. 後院 (Private Subnet)：圍牆高築，沒有對外的大門，只能由前院的管家進入。適合放你的「保險箱」 (例如：資料庫)。
3. 指路牌 (Routing Table)：在莊園的每個路口都設有指路牌，告訴路人：「要去網路世界請往東走」、「要去後院請往西走」。

1. 預設閘道 (Default Gateway)

當一台電腦想要發送資料到「自己社區 (Subnet) 之外」的地方時，它不知道路怎麼走。這時候，它會將封包交給一個專門的出口 $\rightarrow$ 預設閘道。

在現實中，預設閘道通常就是您家裡的 路由器 (Router)。

2. 路由表 (Routing Table)

路由器內部有一張表，記錄了所有目的地的路徑。它的運作邏輯非常簡單：「最精準匹配原則 (Longest Prefix Match)」。

路由表範例：
- 目的地 192.168.1.0/24 $\rightarrow$ 走本地接口 (直接送達)
- 目的地 0.0.0.0/0 (代表全世界) $\rightarrow$ 走 Internet Gateway (IGW)

3. VPC (Virtual Private Cloud)

在 GCP 中，VPC 讓您在雲端定義自己的網路環境。最關鍵的區分在於「可達性」：

我的 GCP VPC
公有子網路 (Public Subnet)
- 有對外出口 (IGW)
- 設備擁有公有 IP
- 用途: Web Server, Load Balancer
私有子網路 (Private Subnet)
- 無對外直接出口
- 設備僅有私有 IP
- 用途: Database, Backend API
$\updownarrow$
路由表 (Routing Table) 管理流量方向
安全金律: 永遠不要把資料庫 (Database) 放在公有子網路中！即便有密碼，暴露在公網上也會增加被攻擊的風險。
反向驗證時間 (架構思考)
請想像你要為一家電商公司設計雲端網路：
  1. 如果你要部署一個「讓客戶瀏覽商品的網站伺服器」，你會把它放在公有子網路還是私有子網路？為什麼？
  2. 如果你要部署一個「儲存客戶信用卡資料的資料庫」，你會把它放在哪裡？為什麼？
  3. 如果私有子網路中的伺服器需要下載軟體更新，但它不能被外界訪問，它應該透過什麼方式連網？ (提示：想想有沒有一種「單向門」設備)
